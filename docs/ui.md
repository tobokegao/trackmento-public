# 画面の作り（frontend/index.html）

見た目・操作・日本語と英語の切り替え。Mac OS 9（プラチナ）風の細部と、実機で踏んだ落とし穴が中心。

（`CLAUDE.md` から分けたもの。2026-09-20。中身は当時のまま）

## 画面の言葉（2026-09-23、HIG に合わせた全体の見直し）

利用者の依頼で、画面・案内ページ・共有ページ・エラー文の日本語をまとめて見直した。基準は
Macintosh Human Interface Guidelines（dev.os9.ca の HIGuidelines、7 章 Button Names と 11 章 Language）。
見直しの指示は `scripts/proofread.py --ui`。

- **「曲」は「トラック」にそろえる**（利用者の指定。「トラック名」「トラックリスト」「{n} トラック」「トラックを探す」）。
  ボタン「トラックを共有」と呼び方がずれていたため。残すのは「作曲」「原曲」「楽曲提供」（決まった言い方）と、
  題名欄の例「私を構成する9曲」・運営者ページの「私を構成する曲」（ネットの決まり文句の引用）。
  **題名欄の例は開くたびに 9 つから 1 つ選ぶ**（`titleExample()`、2026-09-23、運用ボードの open-use）。例が 1 つだけだと、
  ほかの決まりで並べた人が「想定と合っているか分からない」と感じていたため。例は題名そのものなので「曲」のまま。
  言語を切り替えても同じ番号の例を出す。例を足すときは EN 表と `TITLE_EX_I` の数も直す
  **開発向けの文書・コメントは「曲名リスト」などのままでよい**（画面の言葉だけの決まり）。更新情報の過去の記録も直さない
- **押すとファイルを選ぶ窓など続きの窓が開くボタンだけ、名前の後ろに「…」**（「端末から画像を選択…」「並びを読み込み…」
  「ファイルを選ぶ…」「配色パレットを選ぶ…」）。確認だけの窓（「トラックを全て外す」）には付けない。
  **案内文の「」の中で引くときは「…」を付けない**
- 確認窓の文は「何が起きるか＋取り消せるか」（「トラックを全て外します。あとから「元に戻す」で戻せます。」）。
  「よろしいですか？」は使わない。はいの札は結果の動作名（「全て外す」「短くする」）、取り消しは「やめる」
- 「全部」ではなく「全て」（利用者の指定。「トラックを全て外す」）
- エラー文に例外名・HTTP の番号・内部の言葉（cells・README・ホスト名）を出さない。**調べるための情報は `print` でログへ**
  （`_log_5xx` は detail の文をそのまま記録するので、detail から外した分をログに残す）
- 「カラーコード」（「色コード」ではなく）、比率の「自由」（「設定なし」ではなく）、「できあがり」（「出来上がり」ではなく）、
  チェック「トラック名の余計な部分を省く」とボタン「トラック名を短くする」（「蛇足な曲名を除外する」「全曲名を短縮する」ではなく）

## 窓とボタンの決まり（2026-09-23、HIG に寄せた直し。運用ボードの os9-hig）

Inside Macintosh / Mac OS 8 の HIG と突き合わせて直した。

- **Esc は上に重なっている窓から閉じる**（`keydown` の処理。確認窓 → パレット → まとめて取れた窓 → 大きく見る → ソース → シート）。
  以前は確認窓とパレットを扱っておらず、候補のシートの上で確認窓を開いて Esc を押すと、**下のシートだけが閉じていた**。
  窓を足したら、この並びにも足す。送信中の窓（`#up-modal`）は Esc で閉じない（送信を途中で止めるとやり直しになるため）
- **既定のボタンは `.btn-default`**（紙の色 1px のすき間の外に黒 3px の二重枠。ずらした影は消す）。
  Return で押せるのは、窓を開いたときにそのボタンへ焦点を置いているから（ブラウザの既定の動き。JS は足していない）。
  **確認窓の既定は「やめる」**（取り消す側。HIG の決まり）で、「全て外す」「短くする」は黒塗りをやめて普通のボタンにした。
  まとめて取れた窓の既定は「マスに入れる」
- **確認窓は OS 9 の警告の組み方**: 左上に「注意」の 32x32 のドット絵（`.caution`、インラインの SVG。色は
  `--color-mustard`・`--color-ink`・`--color-on-light`）、右に文、ボタンは右下。文には数を入れる（「2 トラックを全て外します。…」）
- **開閉の三角**（`.sub-title`、「URL から」「手入力」）: 閉じていると右、開いていると下（`--disclosure` を 90 度回す）。
  **窓の題名の右の「—」（`.fold`）は OS 9 の collapse box なので形を変えない**（畳んだかどうかは窓の丈で分かる。
  以前は畳むと「+」になっていた）
- **フォーカスの枠は黒 2px を 1px 離す**（`--focus-ring` / `--focus-gap`）。以前は青 3px（`--color-focus`、消した）。
  既定のボタンに焦点があるときは二重枠と重なって太い黒 1 本に見えるが、隣のボタンとは見分けられるのでそのままにした
- **「横 × 縦」の小さな矢印**（`.stepper`、OS 9 の Little Arrows）。ブラウザの数値欄の上下ボタンは消した（端末ごとに見た目が違う）。
  押し続けると 0.4 秒後から 0.08 秒ごとに増減し、**並びを組み直すのは離したときだけ**（16x16 だと 1 回の組み直しに 1 秒かかる）。
  矢印は `tabindex="-1"`（キーボードでは欄の上で ↑↓ を使う）

## 取り消し（2026-09-23、運用ボードの undo-all）

- **並びを書き換える操作の直前に `checkpoint()` を呼ぶ**（frontend の「取り消し」の節）。控えるのはマス・控え（stash）・横 × 縦だけで、
  出力の設定（比率・色など）は入れない。30 段まで（`HISTORY_MAX`）。**並びを書き換える操作を足したら、ここにも足す**。
  今あるのは addTrack・fillEmptyCells・removeAt・swap・onCellTap（入れ替え／移動）・キーボードの入れ替え・resizeGrid・clearAll・trimAll・アーティスト名の候補・編集欄
- 控えは**マスの中身まで写す**。編集欄は `t.title` をその場で書き換えるので、参照のままだと控えまで変わる
- 編集欄は**欄に入ってから最初の 1 字で 1 段だけ**控える（1 字ごとに積むと Ctrl+Z が 1 字ずつになる）。欄の中の Ctrl+Z はブラウザに任せる
- キーは Ctrl/⌘+Z・Ctrl/⌘+Shift+Z・Ctrl+Y。文字の欄と、グリッドと関係ない窓（確認・パレット・取り込み・ソース）では効かせない
- **スマホにはキーが無い**ので、操作のメッセージに「元に戻す」（`undoLink()`）を付ける。押すと 1 段戻る（それまでは操作ごとに別の戻し方を持っていた）
- 並びの読み込み（ファイル・共有）は控えない（出力の設定まで入れ替わるので、マスだけ戻すと半端になる）

## 並びを複数持つ（2026-09-23、運用ボードの grids-multi）

- グリッドの窓の上に「並び」のポップアップメニュー（`#layout-sel`）と「新しい並び」「この並びを消す」。
  **タブにしなかったのは数が決まらないから**（HIG: 項目の数が変わるならポップアップメニュー）。中身はブラウザの select で、
  見た目だけ OS 9 の形（右端の区切り線と下向きの三角、市松の影）にしてある。開いた一覧は端末のものが出る
- 上限 10（`LAYOUTS_MAX`）。256 マスの並びは 1 つ 100KB ほどで、localStorage（5MB）に余裕を残すため
- 保存の鍵: 1 つ目は id `default` で**前からの `trackmento:grid:default` のまま**（入れる前の並びがそのまま 1 つ目になる）。
  2 つ目からは `trackmento:grid:g<16 進 6 桁>`。一覧と開いている並びは `trackmento:layouts`（`{active, list: [{id, title}]}`）
- サーバーの名前: 1 つ目は今までどおり（`u-…` か `default`）、2 つ目からは後ろに `-g……` を付ける（`u-….json` の掃除にそのまま乗る）。
  手元で動かしているときだけ、消した並びのサーバーの控えも DELETE する（公開サーバーは消せない。期限で掃除される）
- メニューの名前は並びの題。題が空なら「並び N」（N は一覧の位置）
- **切り替える前に今の並びを待たずに書き出す**（`flushSave`。保存は 150ms・送信は 1.5 秒遅らせているので、その間に切り替えると最後の変更が落ちる）。
  消すときは逆に、書き出し待ちを止めてから消す（止めないと消したあとに送信が走って戻ってくる）
- **取り消しの控えは切り替えたら捨てる**（控えは並びごとに持っていない。別の並びのマスに戻ってしまうため）。できあがりの窓も閉じる
- 「新しい並び」は出力の設定（比率・色・横 × 縦）を今の並びから引き継ぎ、題とトラックは空
- 「この並びを消す」は確認窓を出す（「「題」（N トラック）を消します。元に戻せません。」、はいの札は「消す」）。並びが 1 つなら押せない
- **共有 URL（`?share=`）を開いたとき、今の並びにトラックがあれば新しい並びとして開く**（以前は今の並びを上書きしていた）。
  上限に達していれば今までどおり今の並びへ
- 並びの読み込み（ファイル）は今の並びに入れる（変えていない）

## キーボードでの並べ替え（2026-09-23、運用ボードの kbd-move）

- マスは **Tab で 1 つだけ止まる**（roving tabindex。`kbdCell` のマスだけ `tabIndex = 0`）。256 マスを全部 Tab で巡らせない
- 矢印で上下左右のマスへ（端で止まる。折り返さない）、Return / Space は**押したのと同じ**（`onCellTap`: 選ぶ・入れ替える・入れる先にする）、
  **Option（Alt）＋矢印でそのマスのトラックを隣と入れ替える**。選んでいたトラックなら選択も付いていき、フォーカスも移る（続けて押せば運べる）
- `renderGrid()` はマスを作り直すので、**グリッドの中にフォーカスがあったら `kbdCell` のマスへ戻す**（無いと 1 手ごとに Tab からやり直し）。
  マウスで押したマスも `kbdCell` にする（次に Tab で戻ったとき、最後に触った所から始まる）
- Delete で外すのは付けていない（× ボタンに Tab で届く。取り消しもある）
- 確かめ方: promo の Playwright（頭なし）で localStorage に並びを入れて開き、矢印・Alt＋矢印・Enter・Ctrl+Z を押す（手元の Chrome は別端末で localhost に届かない）

## 同じトラック・お題・色で並べ替え・共有から受け取る（2026-09-24、運用ボードの ideas-0923）

利用者が 4 つとも実装すると決めた。

- **同じトラックの知らせ**（`dupAt` / `sameTrack`）。トラック名とアーティスト名がどちらも `nkey()` で同じなら同じトラックとみなす。
  **入れるのは止めない**（同じトラックを 2 回並べたい人もいる）。1 つ入れたときは「N 番にも同じトラックがあります。」、
  まとめて入れたとき（プレイリスト・一覧から）は入れたうちの数を括弧で添える（`fillDups` / `dupNote`）。
  マスに入る道は `addTrack` と `fillEmptyCells` の 2 つだけ（入れ替えは数が変わらないので見ない）
- **お題の見本**（題名欄の下のポップアップメニュー `theme-sel`）。選ぶと題名が入り、メニューは「見本から選ぶ…」に戻る。
  題名は**選んだ項目の文字そのもの**（英語表示なら英訳が入る）。`value` が「横x縦」なら大きさも変え（今は「私を構成する9曲」の 3x3 だけ）、
  `t` なら大きさはそのまま（曲数の決まっていないお題。縮めると並べたトラックが外れるため。利用者の判断）。
  **見本は利用者が選んだもの**（9/24、初めに入れた「今年よく聴いた10曲」など 4 つは利用者の依頼で外し、タイトル欄の例を中心に差し替えた）。
  **タイトル欄の例（`titleExamples`）も同じ 10 個にそろえてある**（利用者の依頼）。片方を変えたらもう片方も
  大きさの変更は取り消せるが、題名は取り消しの控えに入っていない（題名の打ち込みを控えに入れていないのと同じ）。
  見本を足すときは `<option>` と `EN` 表の両方に足し、`check_i18n.py` とフォントの作り直しを回す
- **色で並べ替え**（「色で並べ替え」ボタン、`colorKey`）。書き出しと同じ道（`preloadR2Map` → `loadCover(t, 64)`）で 64px の版を取り、
  24x24 に縮めて**鮮やかな画素（明るさ 0.2 以上・彩度 0.25 以上）の色相を 30° ずつ 12 の組に分け、いちばん多い組の平均の色相**で並べる。
  色相は 345° を 0 として数える（赤紫寄りの赤が紫の後ろに回らないように）。鮮やかな画素が 1 割に満たない絵は白黒とみなして後ろに明るい順、
  取れなかった絵は最後尾、空きマスはさらに後ろに寄る。6 枚ずつ並行して取り、同じ画面で押し直したときは控え（`COLOR_KEY`）を使う。
  調べている間に並びが変わったら上書きしない。取り消せる（「元に戻す」）。**小さい版を R2 から読むので Render の転送量はほとんど増えない**
- **共有から受け取る**（Web Share Target、`takeSharedUrl`）。`/manifest.webmanifest`（`backend/main.py` の `MANIFEST`）の `share_target` が
  `/?st_title=…&st_text=…&st_url=…` で開く。3 つをつないで http の URL をすべて拾い、「URL から」の欄に入れて取り込む（スマホではシートを開く）。
  アプリによって URL が `url` に入るもの・`text` に文章ごと入るもの（YouTube など）があるため。**引数に `st_` を付けるのは `?share=<id>` と取り違えないため**。
  使えるのは**ホーム画面に追加した人だけ**で、Android の Chrome 系に限る（iPhone の Safari は `share_target` に対応していない）。
  **Service Worker は置いていない**（Chrome のインストールの条件に入っていない。置くと古い画面が残る心配が増える）。
  アイコンは `icon-192.png` / `icon-512.png`（`scripts/build_icons.py`）
- 確かめ方: promo の Playwright（頭なし）で localStorage に並びを入れて開き、検索から同じトラックを入れる・「色で並べ替え」・お題を選ぶ・
  `/?st_text=…https://www.youtube.com/watch?v=…` を開く。**実機のホーム画面に追加して「共有」から送るのは Android が要る**

## トラック名の一覧（2026-09-23、運用ボードの text-paste・text-copy）

- **表から入れる**（検索ペインの「トラック名の一覧から」、`list-form`）。アーティスト名とトラック名の 2 列の表（表計算の升目。列の順は利用者の希望で検索欄と逆）。
  初めは 3 行、最後の行に打ち始めると 1 行継ぎ足す（上限 20）。表の最下段の「＋ 行を足す」でも 1 行ずつ足せる（20 行で隠れる。先に行を用意したいという利用者の依頼）。各行の右端の「×」でその行を消し、下を詰める。**× は 4 行以上のときだけ押せる**（3 行では消しても空の行が補われて何も変わらず、効かないように見えたため。列と線は残して幅をそろえる。利用者の案）。Return は 1 つ下の升へ、Shift+Return は上へ（押しても探し始めない）。
  **初めは 1 本の文章欄（「アーティスト - トラック名」を 1 行ずつ）だったが、列を分けて打てないと探しづらいと利用者に言われて同じ日に表にした**
- **行を継ぎ足すとき表を作り直してはいけない**。日本語の変換中に欄が入れ替わると変換が切れる（`listRowEl` で 1 行だけ足す）
- 貼り付けは行と列に分ける。タブ区切り（Excel など）は列の順（アーティスト名 → トラック名）に、「トラック名 / アーティスト」「アーティスト - トラック名」の形は
  解いて 2 列に、区切りの無い 1 列ぶんは貼った列に縦に入れる。行頭の番号（`1.` など）と箇条書きの印は外す。1 語だけなら普通に貼る
- 1 行ずつ **iTunes だけ**で引く（ブラウザから直接。`itunesSearch`）。iTunes は約 20 回/分なので**上限 20 行、行の間は 3 秒**
  （英語の画面は米国のストアにもう 1 回引くので 6 秒）。走っている間はボタンが「やめる」になり、押すと止まる
- **マスに入れるのは、トラック名とアーティスト名が `nkey()` でぴったり合ったものだけ**。ほかは先頭の 1 件を候補へ。
  アーティスト名の無い行は同名の別の曲が入りやすいので、必ず候補へ。「A - B」はどちらがアーティストか決めきれないので、
  ぴったり合わなければ入れ替えてもう 1 回引く（逆に解いても、名前を曲名に含む別のトラックが引っかかって空にならないことがある）
- 見つからなかった行と、止めたときの残りの行は表に残す（直してもう一度押せる）。マスに入れたら「元に戻す」を付ける
- **コピー**（「トラック名をコピー」、`text-copy`）。「1. アーティスト - トラック名」を番号順に（アーティスト名が先。表の列の順と同じにしたいという利用者の希望。アーティスト名が無いトラックは「1. トラック名」）。番号はマスの番号と同じで、
  空きマスは飛ばす。絵文字は落とさない（描画用の `oneLine` は使わない）。この形は上の表にそのまま貼り戻せる
- 補助の欄（URL から・一覧から・手入力）は 1 つ開くとほかが閉じる。初めは PC で「URL から」だけ開いている。
  覚えた開閉に無い欄は初期値で埋める（`loadFold`。足した欄が前からの利用者にだけ開いて見えないように）

## 1 つだけ選ぶものはラジオボタン（2026-09-22）

ソース・比率・マスの形・サムネの入れ方（全体とマスごと）・曲名リストは、**Mac OS 9 のダイアログのラジオボタン**の見た目にした

    選択・掴んでの入れ替え・番号バッジ・ドラッグがそのまま効く。閉じるときは説明文の前へ戻す
  - **選択中のマスの編集（`#editor`）も一緒に窓へ移す**。もとの場所は検索ペインの中で、

    入れ物が中身に押し広げられた大きさを返し、そこから決めた枠が窓からはみ出す）。

    そちらが勝ち、1 マス 42px から伸びなかった

    画面が縦に広いほど大きくなる（正方形の並びは画面の高さで決まる）
  - **マスの下限は `ZOOM_MIN_CELL`（48px）と「欄の中で見えていた大きさ」の大きいほう**（2026-09-17）。

    窓の中でスクロールさせる（`.grid` に幅を直接入れる。枠線・指の画面の溝・PC のスクロールバーのぶんも数える）。

    （`__setGridUI` → `#zoom-btn` → `.cell` の幅を測る）

    ごとに localStorage（`trackmento:zoomCell`）へ覚え、覚えた大きさがあれば下の自動の規則より優先する。下限 ZOOM_MIN_CELL、上限は窓の幅。
    指の間の点が動かないようにスクロールを合わせる
  - **横に長い並びは、窓の下が空くぶんマスを大きくして横に送る**（`ZOOM_WIDE_FILL` 0.35 / `ZOOM_WIDE_MAX` 200px、2026-09-20）。

    欄の中の大きさは見ない）。スマホで 1x32 が 330 → 169px（1 画面に 2 マスしか入らなかった）
  - **横にしかあふれない帯は、シートの `touchmove` の番人に通してもらう必要がある**（2026-09-17）。
    番人は「縦にスクロールできる要素の中で始まった touchmove だけ通す」だったので、32x1 の帯（横にしか
    あふれない）が指で動かせなかった（実機で報告）。`overflowX` と `scrollWidth` も見る。

- **指で触る画面（`(pointer: coarse)`）では、スクロールバーを自前で描いて自分で動かす**（`attachTouchScrollbar`）。
  **スマホのブラウザはスクロールバーを「触れる部品」として扱わない**（指の入力はつまみの上にあっても
  中身のスクロールに回る）ので、ブラウザ任せでは掴めない。24px に広げても掴む対象になっていないので効かなかった。

  **上下の矢印（`.tsb-up` / `.tsb-down`）も自前で描く**（2026-09-24、スマホで出ていないと指摘。以前はつまみだけだった）。

  溝が 44 + 48px より短いときは矢印を出さない（`.tsb-short`。つまみが入らなくなる）

  見づらいと報告。PC の `::-webkit-scrollbar-button` も同じだった）。ボタンの面取りの明るい側も `--color-paper` から
  `--color-hl` に替えた（暗い地では paper が地より暗く、光の向きが逆に見えていた）
  **ブラウザのものは `width: 0` で消す**（二重に出る）。PC（`pointer: fine`）では作らない
- **指で触る画面の溝は、スクロールバーが出るときだけ空ける**（2026-09-16 の夜に戻した）。

  - **PC も溝を空けない**（2026-09-16 の夜。`.grid-scroll` の `scrollbar-gutter: stable` をやめた。

    縦にあふれる。スクロールバーのぶん中身の幅が縮んでも「あふれるかどうか」は変わらず、往復しない

  狭く（Material は 48dp、Apple は 44pt）、つまみを掴み損ねて溝を押し、別の場所へ飛んでしまう。
  つまみの最小の長さも 44px にしてある
- UI デザインは Hallmark 方針（仕様書「UI デザイン方針」）。色・フォントは CSS 変数トークン経由、角丸なし
- **明るい色の下地に置く「添え字」は `--color-on-light-2`**（2026-09-16）。選択中のマスの編集パネルは
  地がマスタードなのに、中の見出し（曲名・アーティスト名）と補足が `--color-ink-2` のままだった。
  暗い地の組では ink-2 が明るい灰色になり、**黄色の上に薄い灰色の文字**が乗って読めない（実機で報告）。

- **シート・モーダルを開いている間、後ろの画面をスクロールさせない**（`lockScroll` / `unlockScroll`、2026-09-16）。
  **`body { overflow: hidden }` は効いていなかった**: `html, body { overflow-x: clip }` があるため、html の overflow が
  visible でなく、body の指定が viewport に伝わらない（CSS の決まり）。指の画面では `html.sheet-open { overflow-y: hidden }`

  候補の上で指を動かしても `.sheet-body` が動かなくなった（実機で報告。エミュレータでは再現しない）。
  引き出しの中の `.results` は `overflow: visible` にしてスクロール箱にしない。
  **body を `position: fixed` で固定する手は使わない**。一度やって、実機の Android で候補の窓の中まで
  スクロールできなくなった（エミュレータでは再現しない）。
  **開閉の場所は 6＋6 か所あり、`sheet-open` の class を直接触らずこの 2 つを通す**

## 元に戻す・やり直す・背景の決め方（2026-09-25）

- **「元に戻す」「やり直す」のボタン**はグリッドの下のボタンの先頭に、**小さく右寄せ**で 2 つ（`.grid-actions > .history`、高さ 28px）。
  最初は幅いっぱいにしたが「存在感が大きすぎる」と利用者から。字はドット字の升目の大きさから下げられないので、高さと幅で控えめにした。
  中身は Ctrl+Z / Ctrl+Y と同じ履歴（30 手、`checkpoint()`）。戻せないときは押せない（`syncHistory()`）。
  メッセージの後ろの「元に戻す」は残した。キーボードの無いスマホで 2 手以上戻れず、やり直せなかったのが理由
- **背景の決め方**（`#bg-mode-seg`、`state.bgMode`）は「色を選ぶ」「ジャケットに近い色」「ジャケットと反対の色」「背景なし」の 4 つ。
  **描くのはいつも `bg` / `bgCustom` だけ**で、決め方はその色を決めるためのもの（サーバーの描画は `bgMode` を見ない。`GridOptions.bgMode` は覚えておくためだけ）
  - ジャケットの色: 並んだジャケット（先頭 64 枚、64px の版）の鮮やかな画素を色相で 12 に分け、多い組から最大 4 つをその組の平均の色で候補にする。
    「ほかの候補」で次へ。並びが変わると `save()` から取り直す（`autoBgSoon`、ジャケットの並びが同じなら何もしない）。白黒ばかりなら平均の明るさの灰色 1 つ
  - 反対の色: 色相を 180° 回す（彩度・明度はそのまま）。灰色は明るさを反転する
  - 背景なし: `bgCustom` を白にする（**共有の画像は白い地**。JPEG は透明にできない）。ブラウザ描画は `renderShareCanvas(…, { transparent: true })` で透明に描き、
    送る JPEG だけ白い地に敷く（描くのは 1 回）。「できあがり」の枠は透明な PNG を市松の上に出し（`#output-img.is-clear`）、「画像を保存」は PNG。
    サーバー描画に落ちた端末は白い地の JPEG のまま
  - 「色を選ぶ」から離れるときは選んでいた色を覚え、戻ったら戻す（画面を開いている間だけ）。見本を押すと「色を選ぶ」に戻る
  - グラデーションの背景は「足さない見た目」に当たるので入れていない。好きな画像を背景にする案は利用者から出ている（未着手）
- **スマホでマスを選んだら、編集欄（「選択中のマス」）の頭が見えるところまで送る**（`revealEditor()`、2026-09-25、利用者の指摘）。
  編集欄はグリッドの枠の下に出るので、枠を画面の下端まで送って使っていると画面の外に出て、選んだことに気づきにくかった。
  送るのは欄の頭が画面の下から 220px（画面の高さの 3 割まで）のぞく分だけ（まるごと見せるとグリッドが上に逃げ、次に入れ替える先のマスが押しづらい）。
  頭がすでに下から 120px 以上見えていれば送らない。拡大窓の中は窓の中に出るので送らない
- **背景の画像**（決め方の 5 つ目「画像」、2026-09-25、利用者の案）。「画像を選ぶ…」で端末の画像を `/upload` に上げ（撮影日時などを消して長辺 2048px に縮める。手入力と同じ仕組み）、
  `bgImage` に `/uploads/…` を入れる。**受け付けるのはうちに上げた画像だけ**（`grids.py` の `_UPLOAD_RE`。よそのサーバーの画像をサーバーに取りに行かせない）。
  書き出しは枠いっぱいに切り抜き、**背景色の上に半分の濃さ**（`BG_IMAGE_ALPHA` 0.5）で重ねる。背景色には画像の平均の色を入れる（文字の色がそこから決まる）。
