# 画面の作り（frontend/index.html）

見た目・操作・日本語と英語の切り替え。Mac OS 9（プラチナ）風の細部と、実機で踏んだ落とし穴が中心。

（`CLAUDE.md` から分けたもの。2026-09-20。中身は当時のまま）

## アーティスト名の候補（2026-09-21）

編集パネルに出る。**YouTube とニコニコ動画のマスだけ**。

- **転載元**は取り込んだ時点で分かっている（`Track.origin`。概要欄から。`backend/sources/video.py`）。
  待ち時間なしで「Pangelino（転載元 sm12305503）」のように候補に並ぶ
- アーティスト名が**チャンネル名っぽい**とき（宣伝の文句か「公式チャンネル」「Channel」を含む）だけ、
  題の中の名前（`/` 区切りと `【】` の中身）も候補にする。**絞らないと**【魂音泉】（サークル名）や
  【ハルトマンの妖怪少女】（原曲名）が全マスで候補に出て鬱陶しい
- **「元の投稿を探す」**でニコニコの同じ題の古い投稿を引く（`/artist-candidates`）。
  押したときだけ。結果は 7 日覚える
- 候補を押すとアーティスト名が入れ替わり、直後の「元に戻す」で戻せる

**候補は縦に積む**。名前が長いので横並びだと編集パネルの幅からはみ出して右が切れる。

## マスの形と絵の入れ方（2026-09-21）

書き出しオプションの「比率」の下に**「マスの形」**（正方形 / 横長 16:9。`options.cellRatio`、既定は正方形）。
横長を選んだときだけ**「絵の入れ方」**（切り抜く / ぼかして埋める。`options.cellFit`、既定は切り抜く）が出る。

- 編集パネルに**「このマスの絵の入れ方」**（全体に従う / 切り抜く / ぼかして埋める。`Track.fit`）。
  **文字の入ったジャケットだけ埋めたいとき**に使う。値は並びに保存されるので、サーバー描画とも必ず一致する
- 画面のマスにも同じ見た目を出す。下地に同じ絵を `object-fit: cover` ＋ `filter: blur()` で敷き、
  本体は `contain`。**下地は `transform: scale(1.12)` で外へ広げて `overflow: hidden` で切る**
  （マスちょうどだと縁がにじんで四角の枠がぼやける。書き出し側の `coverBlurPad` と同じ考え方）
- 下地を敷くと重なり順が変わるので、番号・×・曲名の帯は `z-index: 2` で前に出す
- 「出力サイズ」の「マスの大きさ」は、横長のときだけ `幅 × 高さ` で出す

### 書くときの落とし穴

- **`hidden` 属性は `.seg { display: flex }` に負ける**。要素の `display` を具体的に指定していると、
  `hidden` の既定（`display: none`）が効かない。`.seg[hidden], .note[hidden], .field[hidden] { display: none; }` で打ち消す
- **画面と書き出しの見た目をそろえる**。Canvas 側だけ直すと、画面では切り抜き・書き出しでは
  ぼかし埋め、という食い違いが起きる（実際に一度そうなった）

## 曲名の刈り込み（2026-09-21）

書き出しオプションの「表示」に**「蛇足な曲名を除外する」**（既定は入り。`options.trimNames`）。
【東方Vocal】のような分類のタグ・[Music Video] のような媒体の表記・「- Topic」のような
チャンネル名の尾・曲名の中のアーティスト名の重複を外す。**サークル名・原曲名・歌唱者は残す**。

- **データは元のまま**。画面のマスと書き出しは刈った題を使い（`viewCells()`）、
  **編集パネルの入力欄には元の題が出る**（直す対象は元のデータなので）
- 「みんなのグリッドに載せる」の右に**「全曲名を短縮する」**。刈った結果をデータに書き戻す。
  押すと件数を出して確認し、直後のメッセージの「元に戻す」で戻せる（「マスを全部外す」と同じ作り）
- 共有ページ（`/s/<id>`）の曲リストも、共有したときの `trimNames` に従う。
  この項目が無い古い共有は刈る側（画像と曲リストの題が揃う）

### 書くときの落とし穴

- **`new RegExp` に渡す文字列のバックスラッシュ**。`"\\s"`（2 文字）が `"\s"`（1 文字）に減ると
  JS では ただの `"s"` になり、黙って別物の正規表現になる（「FULL ver.」が外れなくなっていた）。
  正規表現リテラルの断片を `.source` でつなぐ書き方は、**断片単体が正規表現として妥当でないと**
  （`/^\s*(?:/` など）パースできないので使えない
- **`new RegExp` の文字列に生の全角文字を書かない**。`scripts/check_i18n.py` が「訳し忘れの日本語」と
  読む。`　` は `　`、`／` は `／`、`・` は `・`
- **確認の窓の既定の文言は `tr()` の中に直接書く**。定数に逃がすと `check_i18n.py` が「包み忘れ」と読む

- フォント: Web は `fonts/split/`（`scripts/build_fonts.py` が IBM Plex Sans JP / DotGothic16 を unicode-range で分割した WOFF2 ＋ `fonts.<hash>.css`）を `<!--__FONT_LINK__-->` 経由で読む。**`frontend/index.html` の固定文字（ラベル・説明文）を変えたら次の 3 つを順に実行する**
  1. `python scripts/build_fonts.py` … 断片と `fonts.<hash>.css` を作り直す（先頭断片に UI の全文字を入れる設計。忘れると初回表示で断片を大量に読む）
  2. `.venv/Scripts/python scripts/upload_fonts_r2.py` … 増えた断片を R2 に上げる。**これを忘れると本番でフォントが 404 になる**（断片名にハッシュが入るので、文字が変わると別ファイルになる）
  3. `PYTHONUTF8=1 .venv/Scripts/python scripts/check_i18n.py` … 日本語の文言と EN 表のずれを見つける。
     **EN 表は日本語の文面そのものが鍵なので、文言を 1 文字直すだけで英語がそこだけ日本語に戻る**（警告は出ない）

  **ピクセルフォント（Silkscreen）も R2 から配る**（2026-09-15）。分割していないので `<link>` ではなく、
  `main.py` の `index()` が HTML 内の `@font-face` の **woff2 の URL だけ**を R2 に差し替える
  （ttf の控えはサーバーのまま。woff2 を読めない環境用で、まず使われない）。共有ページは
  `share.py` の `_silkscreen_url()`。点検で `/fonts/Silkscreen-Bold.woff2` が 2 時間に 253 件出ていたのを移した。
  **ファイル名にハッシュが入っていない**ので、フォント自体を差し替えたときは `--force` で上げ直す

  断片は R2 から配る（`/fonts-css/<name>` が CSS の `src` を R2 の公開 URL に差し替えて返す）。Render 前段の Cloudflare は Web Service の応答をキャッシュせず、フォントが新規訪問 1 回あたり 210KB（実測）で転送量の大半を占めていたため。`FONTS_FROM_R2=0` で従来どおりサーバーから配る。R2 側の CORS 設定と、CSP の `font-src` / `connect-src` への公開 URL の追加が前提（`_r2_origin()` が組み立てる）。共有画像の描画前は `loadShareFonts` が描く文字を渡して必要断片だけ読む。サーバー描画は `fonts/*.ttf` のまま。共有ページはシステムフォント（Silkscreen のみ読む）

- 日本語 / 英語の切り替え（2026-09-14）
  - **画面**: `frontend/index.html` の `EN` 表と `tr()`。**日本語の文面をそのまま鍵にして英語を引く**ので、原文がコードに残る。
    `${…}` を含む文面は `` tr`…` `` とタグ付きテンプレートで呼び、鍵は raw を `"{}"` でつないだもの。英語側の差し込み位置は
    `{0}` `{1}` … で書く（語順が日本語と変わるため）。**関数名は `tr`**（`t` はトラック変数として多用されているので使えない）
  - HTML に直接書いた文言は起動時に `snapI18n()` で控えを取り、`applyI18n()` が差し替える。
    **後から足した利用者のデータ（曲名・アーティスト名）は控えに無いので触らない**という作り
  - `SOURCE_LABEL` / `SWATCHES` の値は日本語のまま持ち、**使う側で `tr()` を通す**。表は起動時に 1 回しか評価されないため、
    リテラルを `tr()` でくるむと切り替えに追従しない
  - 言語を変えたら `reRenderForLang()` が描き直す。**`renderResults` は候補が空のときに呼ぶと「該当なし」に化ける**ので、
    件数があるときだけ呼ぶ
  - `__RETENTION__` は `main.py` が HTML 全体を置換するので、EN 表の鍵と DOM の文字列は必ず同じ値になる（そこは心配しなくてよい）
  - 共有ページの曲名リストは、**元のページ（YouTube・ニコニコ・Bandcamp など）へのリンク**になっている
    （2026-09-15、利用者の要望）。`external_url` は利用者のデータなので **http(s) だけ通す**（`javascript:` を弾く）。
    外部へ出すリンクには `noopener noreferrer nofollow` を付ける。
    **リンクだと一目で分かるようにする**（2026-09-15）。色は変えず、曲名に点線の下線と外部リンクの印（↗）を付け、
    触れたら下線を実線にする。リンクの無い曲と並んでも一覧が騒がしくならない。
    **印は CSS の `content` に生の ↗ を書く**（`97` と書くと Python が `` を 8 進として食べ、制御文字になる）
  - **共有ページ・案内ページ**（`backend/share.py` の `TEXT` と `t()`）はサーバーで組み立てるので別仕組み。
    `main.py` の `_lang_for(request)` が **開いた人の Accept-Language** で選ぶ。共有ページは受け取った人が開くものなので、
    共有した人が画面で選んだ言語ではなく開く人の設定に合わせる
  - 連絡先は日本語 `/ja/about/`・英語 `/about/` でページが別。画面側は `#about-link` の href を切り替える
  - **`?lang=en` / `?lang=ja` を付けると言語を指定できる**（2026-09-15）。画面（`frontend/index.html`）は
    localStorage にも覚え、共有ページ・案内ページ（`main.py` の `_lang_for`）は Accept-Language より優先する。
    **日本語環境の人に英語の画面を見せるリンクが作れる**（海外向けの案内、動画や SNS からの誘導）。
    例: `https://trackmento.com/?lang=en`

- **パレット（背景色の 8 色 ＝ 画面の配色）**（2026-09-15、2026-09-16 に 6 → 8 色）。背景色の見出しの
  「パレット」ボタンでオーバーレイが開き、8 色ひと組を選べる。**地の色（クリーム）と文字の色（黒）も組に入る**。
  組み込みは「リソ」（もとからの色）と「ポップ」（色見本から取った色）。自作の組も作れる
  - **画面に使うのは「地」と装飾の 6 色まで。「黒」は画面には使わない**（2026-09-16 に実機の報告を受けて）。
    `--color-ink` は枠線・文字・面取りの黒で、OS 9 のプラチナのグレー（`--color-bar` / `--color-bar-dark` /
    `--color-hl`）と**組にして調整してある**。ここだけ組ごとに変えると黒が 2 種類混ざり、
    **枠の手前に別の線が浮く**（「グリッド枠の下に白い隙間」の報告。実測でジャケットの黒 (18,23,27) と
    枠線 (27,36,48) のあいだに余白の帯が挟まって見えていた）。`PALETTE_SLOTS` の 2 番目は `null`
    - 組の「黒」は**書き出し画像の背景色の選択肢としては生きている**（ポップなら `charcoal`）
  - **下地の色（`paper-2` / `paper-3`）だけ地から作る**（`PALETTE_MIX`。6% と 12%。
    混ぜる相手は組の黒ではなく**固定の黒**）。**枠線（`rule` / `rule-2`）と添え字（`muted`）は作らない**。
    プラチナのグレーと組にして調整してあるので、地に合わせて動かすと面取りが二重線に見える
  - 番人は**組の地と、その地に合う文字の色**の明るさの比で測る。`PAL_MIN_RATIO`（7:1）に
    満たない組は地も差し替えず、一覧にその旨を出す（黙って無視しない）
  - **地が暗い組では、画面のプラチナごと暗い側に入れ替える**（2026-09-16）。`applyPalette` が
    地の明るさを見て `:root` に `data-ground="dark"` を付け、CSS の `:root[data-ground="dark"]` が
    12 個のトークンを暗い地むけの値にする。**判定はサーバー側の描画（`render.py` の `light`、
    明るさ 0.55）と同じ規則**にしてある（画面と出力で印象が食い違わないように）
    - **単純な反転ではなく、暗い地むけに作り直した組**。面取りの明るさの並び
      （明るい白 ＞ 暗い白 ＞ 地 ＞ 濃いグレー）は、光が左上から当たるという前提ごと保つ
      （74% ＞ 58% ＞ 38% ＞ 20%）
    - **影は `--color-ink` から `--color-shadow` に分ける**。ink をそのまま使うと、暗い地では
      ink が明るいので**影が光って見える**。`--shadow` / `--shadow-sm` とボタンの市松
      （`.btn::after`）が対象
    - **暗い地の影は「地より明るい中間のグレー」**（58%）。地より暗い色にすると、
      地がもう十分暗いので**影がまったく見えない**（最初 8% にして実機で報告された）。
      中間のグレーなら、暗い面の縁に落ちた影として読める。**8% → 34% → 48% → 58% と 3 回上げている**：
      市松で敷くので見た目の明るさは地と混ざって半分ほどに落ち、数字どおりには出ない
    - **色つきの下地に置く文字は `--color-on-light` / `--color-on-dark`**。マスタードの帯・バッジ・
      選択中のマスの番号など、accent の上に文字を置く所は「明るい下地なら暗い文字」で固定する。
      `--color-ink` を直に使うと、暗い地の組で白い文字が黄色の上に乗って読めなくなる
    - 組み込みの「ナイト」がこの経路を通る唯一の組。**色の名前を足すときの 5 か所**は上と同じ
  - **6 色で保存された古い組は、読み込んだあとに先頭へクリームと黒を足して 8 色にする**（`migratePalettes`）。
    `TOKENS_RGB` はパレットの定義より後ろで作るので、**読み込みのときに直すと TDZ で落ちる**。
    最初に使うところ（起動時の `applyPalette` の直前）で直す
  - **色の名前を足したら 5 か所**: `backend/render.py` の `TOKENS`、frontend の CSS 変数と `TOKENS_RGB`、
    `backend/grids.py` の `BG_KEYS`（ここに無いと共有の読み込みで弾かれる）、`cli.py` の `--bg`。
    ポップの地と文字は `ivory` / `charcoal`
  - 組を切り替えると**背景色の見本と画面の装飾色が同時に変わる**。装飾色は `--color-mustard` などの
    6 スロットの中身を差し替える形（36 か所ある参照はそのまま）。**見本だけは固定値で塗る**
    （`var(--color-…)` にすると、組を変えたときに見本の色まで変わってしまう）
  - 自作の組は 16 進で持ち、選ぶと**カスタムカラー**（`bg: "custom"` ＋ `bgCustom`）として保存される。
    描画の仕組みは触っていない。組み込みの色は今までどおり色の名前で保存する
  - **読み込んだ並びの色は、今の組に入っていなくても受け付ける**（`ALL_BG_KEYS`）。別の組の色なら組ごと切り替える。
    ここを今の組だけで見ていたとき、`rose` の共有を開くと `paper` に戻って**サーバー描画と 93% ずれた**
  - 8 色は「コピー」で色コードとして書き出し、貼り付けて読み込める（区切りは何でもよい。8 つちょうど必要）
  - **ファイルでも渡せる**（2026-09-19、利用者の要望）。組ごとの「保存」で `trackmento-palette-<名前>.json`
    （`{trackmento: "palette", v: 1, name, colors: [8 色]}`）を落とし、「ファイルから読み込む」で自作の組として足す。
    JSON でなくても、色コードが 8 つ並んだ文字なら読む（20KB を超えるファイルは読まない）
  - 自作の組の色は、**その色を押すとオーバーレイの中に HSV のつまみが開く**（もう一度押すと閉じる）。
    `input type="color"` は使わない。**OS の色ダイアログは画面を止めるので、動画の撮影でも都合が悪い**
    （カスタムカラーのつまみと同じ部品・同じ操作にそろえてある）
  - 色の値は **`backend/render.py` の TOKENS・frontend の CSS 変数・TOKENS_RGB の 3 か所**にある。片方だけ変えない

- **つまみ（余白・マスの間隔・色の指定）は掴まないと動かない**（`thumbOnly`）。`input[type="range"]` は
  溝を押した位置へ値が飛ぶのが既定だが、スマホで並びを触っているときに指が当たって値が変わる、と報告があった。
  つまみの上でない `pointerdown` は握りつぶす。**キーボード（矢印キー）はこれまでどおり効く**
  - **入力は `input` ではなく上に重ねた受け皿で受ける**（2026-09-15、最終形）。
    `input[type="range"]` を `.range-wrap` で包み、同じ大きさの `.range-pad` を重ねて、
    **`input` 自身は `pointer-events: none`**。指もマウスも届かないので、ブラウザ既定の
    「押した位置へ値が飛ぶ」が**起こりようがない**。掴んでいる間の色は `.is-grabbed` で出す
    （`:active` は入力を受け取らなくなったので効かない）。
    **キーボード（矢印キー）は触っていないので今までどおり効く**
    - **つまみの色に `:active` を使ってはいけない**。`<label for>` を長押しすると、押されたのが
      見出しでも関連付けられた `input` が `:active` になり、**つまみが押されたように見える**
    - そこへ至るまでに `pointerdown` / `touchstart` / `touchmove` の `preventDefault` と
      CSS の `touch-action: none` を順に足したが、**Android の実機ではすり抜けが残り 3 回報告された**。
      エミュレータでは毎回すべて再現しない。**止める側で戦わず、届かなくする**のが正解だった
    - 途中、`touch-action: none` を書き足したのに**同じ詳細度の `touch-action: pan-y` が後ろに残っていて
      負けていた**（＝その間の対策はどれも効いていなかった）。同じ属性を 2 か所に書かない
    - 「つまみの上なら既定に任せる」形も駄目だった: つまみには幅があるので**押しただけでも値がずれ**、
      指の太さぶんの遊び（±8px）を足していたので**つまみの真横の溝でも動いた**
  - **見出しの文字（`<label for>`）の `pointerdown` も止める**。label は押すと中の部品を動かす決まりなので、
    「余白 16 px」の行を長押しするとつまみが押されたように見えていた
  - **`touchstart` だけでなく `touchmove` も止める**。Android では「タップして滑らせる」と
    既定の追従が効いて動いてしまう（実機で報告。エミュレータでは再現しなかった）。
    CSS でも `input[type="range"] { touch-action: none }` にして、ブラウザ独自のジェスチャを切る
  - 確かめ方: `node promo/test_slider2.mjs`（実機相当の 412x915 / dpr 2.625 / タッチ）。
    溝の連打・つまみの真横からのスライド・見出しのタップのどれでも値が変わらず、

  地が暗いパレットだと黒地に黒い文字になる（URL の欄で報告）
- **ソースのボタンは格子（grid）で並べる**。`.seg` の `flex: 1 1 auto` は「最後の行の項目を行幅いっぱいに
  広げる」ので、4 つ目（VocaDB）だけが 1 行を占めて幅が不揃いに見えた（本番のソースは 4 つ。`DISCOGS_TOKEN` を置いた環境では Discogs が増えて 5 つになる）
- **画面の高さに合わせる頭打ちは `dvh` ではなく `svh`**（2026-09-16）。`dvh` は「今この瞬間の
  画面の高さ」なので、スマホでスクロールしてアドレスバーが隠れると値が増える。共有できた画像の
  `max-height: 70dvh` がそれで伸び縮みし、**下の「URL をコピー」などがスクロールのたびにずれていた**
  （実機の録画で確認）。候補の一覧（`.results`）も同じ理由で `svh` にしてある。
  オーバーレイ（モーダル・シート）は画面を覆うので `dvh` のままでよい
- **`XMLHttpRequest` には必ず `timeout` を入れる**。既定は「無制限」で、応答が返らないと
  送信中の窓が出たまま永久に止まる（実機で「この画面から動かない」と報告）。
  3 分の時間切れ・経過秒の表示・「やめる」（`abort`）の 3 つを入れてある
