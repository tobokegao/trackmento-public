# マスの形を 16:9 にもできるようにする

2026-09-21

## 何を直すか

マスは正方形（`CELL_PX = 600`）に決め打ちで、ジャケットは `_cover_fit`（CSS の `object-fit: cover` 相当）で
中央を切り抜いている。

YouTube とニコニコ動画のサムネイルは 16:9 なので、**左右が 28% ずつ切られている**。
動画のサムネイルは文字を左右に置いたものが多く、切ると読めなくなる。
動画サイトの曲を中心に並べる人には、マスも 16:9 のほうが合う。

## 何をするか

**並び全体で「マスの形」を選べるようにする**（正方形 / 16:9）。マスごとではなく全体で 1 つ。
マスごとに変えると格子の段がそろわず、石畳のようになって割り付けを作り直すことになる。

### 決めたこと

- options に `cellRatio`（`"1:1"` 既定 / `"16:9"`）。グリッド JSON と共有 JSON に入るので、
  共有した並びを開き直しても同じ形になる
- **幅は変えない**。`CELL_W = 600` のまま、`CELL_H` を `600`（1:1）か `338`（16:9）にする
- 16:9 のマスに正方形の絵が来たら、**左右をぼかした引き伸ばしで埋める**（YouTube の再生画面と同じやり方）。
  切ると、アルバムアートは中央に絵があるので損なう
- **ぼかし埋めは 16:9 のマスのときだけ**。正方形のマス（既定）は今までどおり中央で切る。
  今ある並びと共有画像の見た目を変えないため

### マスの寸法

16:9 は **600 × 338**。600 × 337.5 の小数を避けるための丸めで、実比は 16:9.01（誤差 0.15%）。
見た目には分からない。

幅を変えないので、**幅を基準にしている式はそのまま効く**。

| 基準 | 何 | どうするか |
| --- | --- | --- |
| 幅 | タイトルの大きさ（マスの幅の 4.5%・上限 96）、`_mod_pad`、サイドバーの幅、`_title_cap` | そのまま |
| 高さ | `gh = rows * CELL_H + (rows - 1) * g` | `CELL_H` に差し替え |
| 高さ | 行の送りをそろえる `_snap_lead(…, CELL_PX + gap)`、`_slab_rows` の `pitch` | `CELL_H + gap` に差し替え |
| 短辺 | 番号バッジ・曲名の帯・× を出すかの判定（`OVERLAY_MIN_PX` など） | **短辺基準に変える**。今の幅基準だと 16:9 で潰れた帯が出る |

`WRAP_CELL_OK` / `WRAP_CELL_KEEP`（回り込みでマスをどこまで小さくしてよいかの下限）は
**短辺基準**にする。幅で見ると 16:9 のマスが実際より大きく見積もられる。

### ぼかし埋め

絵の比とマスの比が違うときだけ:

1. 絵を cover でマス一杯に拡大し、**ぼかす**（半径 = マスの高さの 6%、論理 px）。これを下地にする
2. contain した絵（マスの高さに合わせ、幅は成り行き）を中央に重ねる

- サーバー: `PIL.ImageFilter.GaussianBlur`
- ブラウザ: `ctx.filter = 'blur(Npx)'`

半径は**論理 px で決めて、両方で `scale` を掛ける**。絶対 px で書くと出力サイズごとに
ぼけ方が変わり、サーバー描画とブラウザ描画がずれる。

PIL の `GaussianBlur` と Canvas の `blur()` は完全には一致しない。`scripts/compare_render.py` の
突き合わせ（6px のぼかし後に比べる。基準 1%）を**実測して確かめる**。ぼかした帯は低周波なので
出にくいはずだが、1% を超えるなら比較のときだけ下地を平均色で塗る逃げ道を用意する。

### 画像のキャッシュ

**変えなくてよい**。`cache.set_image` が持っているのは原寸（動画サムネイルの黒帯だけ切ったもの）で、
マスの形に切り抜くのは `_cover_fit` のメモリ上。形を変えても同じキャッシュから作れる。

## どこを直すか

### サーバー

| ファイル | 何を |
| --- | --- |
| `backend/render.py` | `CELL_PX` → `CELL_W` / `cell_h(doc)`。`_cover_fit(img, w, h)` の呼び出しに高さを渡す。ぼかし埋め `_cover_blur_pad` を足す。`layout()` の `gh`・`pitch`・`_snap_lead` |
| `backend/grids.py` | `GridOptions` に `cellRatio`（`"1:1"` / `"16:9"` のみ受ける） |
| `backend/share.py` | 共有 JSON に入る（options 経由なので自動） |
| `cli.py` | `render` / `share` に `--cell 1:1|16:9` |

### ブラウザ

| どこ | 何を |
| --- | --- |
| `frontend/index.html` の `CELL_PX = 600` | `CELL_W` / `CELL_H` に分ける（**`renderShareCanvas` と対で直す**） |
| マスの CSS | `aspect-ratio` を `cellRatio` から切り替える |
| 書き出し設定 | 「マスの形」（正方形 / 横長 16:9）のラジオ 1 つ |
| ぼかし埋め | `ctx.filter = 'blur(Npx)'` で下地 → 絵を中央に |

### 画面の見た目

16:9 を選ぶと格子が横長になる。10x10 なら塊の比が 10:5.6 になるので、
出力の比率（`ratio`）との噛み合わせは `layout()` の探索が自動で追う（`gw` / `gh` から動くため）。
**縦長の比率（9:16）× 16:9 のマス**は塊が極端に横長になるので、実際に組んで確かめる。

## 突き合わせ

- `scripts/compare_render.py` に 16:9 のマスの組を足す（正方形の絵が混ざるもの・動画サムネイルだけのもの）
- `scripts/compare_layout.py` にも同じ組を足す

## 画面と文書

- `frontend/index.html` を変えるので `scripts/build_app.py` → `scripts/upload_app_r2.py`
- 固定文字（「マスの形」「正方形」「横長 16:9」）を足すので `scripts/build_fonts.py` →
  `scripts/upload_fonts_r2.py` と `scripts/check_i18n.py`
- `backend/pages.py` の `CHANGES` に 1 行（手順はスキル `/updates`）
- `docs/layout.md` に寸法と短辺基準の判定を、`docs/ui.md` に設定の場所を書く
- `CLAUDE.md` の「二重実装の一覧」の「色・比率・`CELL_PX` / `GAP_PX` / `MAX_SIDE`」の行を
  `CELL_W` / `CELL_H` に直す

## やらないこと

- マスごとに形を変えること（格子の段がそろわない）
- 4:3 / 3:4 / 9:16 を足すこと（出力の比率設定と似た選択肢が 2 列並んで迷う）
- 正方形のマスのぼかし埋め（今ある並びの見た目が変わる）
- ソースから形を自動で決めること（曲を 1 つ足しただけで格子の形が変わる）
