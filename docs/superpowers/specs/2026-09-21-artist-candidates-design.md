# アーティスト名の候補を出す（転載動画の元の投稿者を含む）

2026-09-21

前提: [曲名・アーティスト名の蛇足を外す](2026-09-21-trim-names-design.md)。
あちらは**規則だけで確実に直せるもの**を扱う。こちらは**確実には決められないもの**を、
利用者に選んでもらうための仕掛け。

## 何を直すか

YouTube から取り込んだ曲のアーティスト名は、oEmbed の `author_name`（チャンネル名）そのまま
（`backend/sources/video.py`）。チャンネル名がアーティスト名でないことがある。

### 1. チャンネル名が宣伝文・レーベル名

規則で直せるものは spec 1 の A1・A2・G が拾う。拾えないものが残る。

```
題    : 童遊（めらみぽっぷ＆いお ver.）
作者欄: RD-Sounds / 凋叶棕 Official        ← Official が末尾でないので R2 が効かない
```

### 2. 転載

もっと難しいのがこれ。動画の投稿者が、曲を作った人とは限らない。

```
題    : 【ニコカラ】物凄い狂っとるフランちゃんが物凄いうた（OnVo）【字幕大】
作者欄: qfeuille3_v2 🥐⚓                   ← 転載した人
正しい: Pangelino（ニコニコ動画 sm12305503 の投稿者）
```

**転載の向きは 4 通りある**。「ニコニコから取ったものは投稿者が正しい」とは言えない。

| 向き | 例 | この設計で拾えるか |
| --- | --- | --- |
| ニコニコ → YouTube | 上の例 | 拾える |
| YouTube → ニコニコ | YouTube の動画がニコニコに転載される | 拾える（同じ題の古い投稿として） |
| ニコニコ → ニコニコ | ニコニコ内での転載・再投稿 | 拾える（同じ題の古い投稿として） |
| YouTube → YouTube | YouTube 内での転載 | **拾えない**（下の「やらないこと」） |

転載かどうかは**題からも投稿者名からも分からない**。YouTube の概要欄には書いてあることが
多いが、`video.py` が使っているのは oEmbed（`title` と `author_name` だけ）で、概要欄は取れない。
取るには動画ページの HTML を読むことになり、規約の面でも壊れやすさの面でも採らない。

そこで手がかりを**投稿日**に取る。同じ題の動画のうち**いちばん古いもの**が元である見込みが高い。
確実ではない（元が消えて再投稿されたもの、権利者が後から上げ直したものがある）ので、
**候補として出すだけで自動では差し替えない**。

## 何をするか

**候補を出して利用者が選ぶ**。自動では差し替えない。間違った名前を黙って載せるのが
いちばん悪い（消すだけの刈り込みと違い、差し替えは誤りを作る）。

### いつ候補を出すか

出どころで 2 つに分ける。

**題の中の名前**は、マスのアーティスト名に**チャンネル臭**があるときだけ勝手に出す。

- spec 1 の A2 の宣伝の文句を含む
- `公式チャンネル` `Official` `Channel` `チャンネル` を含む

絞らないと、`【魂音泉】`（サークル名）や `【ハルトマンの妖怪少女】`（原曲名）が
全マスで候補に出て鬱陶しい。100 曲の並びで実際にそうなった。

**ニコニコ動画の古い投稿**は、**どのマスでも「元の投稿を探す」を押せる**ようにする。
転載は投稿者名からは分からないので、チャンネル臭で絞ると取りこぼす。
引くのは押したときだけなので、押せる所を広げても負荷は増えない。

### 候補の出どころ（2 つ）

#### 1. 題の中の名前（すぐ出る）

題の `/` 区切りの部分と `【】` の中身から、spec 1 の刈り込みを通したもの。
問い合わせが要らないので、編集パネルを開いた時点で出せる。

#### 2. ニコニコ動画の古い投稿（押したときだけ引く）

編集パネルの「元の投稿を探す」を押したときだけ、ニコニコ動画を引く。
**自動では引かない**（100 曲の並びで 100 リクエストになる）。

**マスの出どころで絞らない**。ニコニコから取ったマスも対象にする（ニコニコ内での転載や、
YouTube からニコニコへの転載があるため）。ニコニコのマスでは、そのマス自身の動画が
結果に含まれるので、**それより古い一致があるときだけ**候補を出す。

##### 引き方

1. **スナップショット検索 API** で題を検索

   ```
   https://snapshot.search.nicovideo.jp/api/v2/snapshot/video/contents/search
     q       = 刈り込みを通した題
     targets = title
     fields  = contentId,title,userId,startTime,viewCounter
     _sort   = -viewCounter
     _limit  = 10
     _context= trackmento
   ```

2. **一致度で絞る**。正規化した題どうしの**共通接頭辞の長さ ÷ 長いほうの長さ**。
   再生数順のままだと別の動画が 1 位になる（この例では「ニコ静ツアー」版が 121 万再生で 1 位）
3. 絞ったものを**投稿日の古い順**に並べ替える。元の投稿がいちばん古い見込みが高い
4. 上位 **3 件**だけ、既存の `NICO_THUMBINFO`（`getthumbinfo`）で投稿者名（`user_nickname`）に変換
5. 投稿者名・動画 ID・投稿日を候補として出す。マス自身の動画より新しいものは出さない

##### 実測（2026-09-21）

`物凄い狂っとるフランちゃんが物凄いうた` で `totalCount` 65 件。

| 動画 | 題 | 一致 |
| --- | --- | --- |
| `sm12305503` | `【ニコカラ】物凄い狂っとるフランちゃんが物凄いうた(OnVo)【ななひら】` | 共通部分が YouTube 題の全長 → **1 位**。投稿者 `Pangelino`（正解） |
| `sm12298171` | `【東方ニコカラ】物凄い狂っとるフランちゃんが物凄いうた【^p^】(on vocal)` | `(OnVo)` と `(on vocal)` で分岐 → 2 位。投稿者 `両義_04` |
| `sm12085793` | `ニコ静ツアー - 物凄い狂っとるフランちゃんが物凄いうた` | 頭が違う → 下位（再生数は最多） |

### 画面

編集パネル（選択中のマス）に出す。

```
07 選択中のマス
曲名   [ 物凄い狂っとるフランちゃんが物凄いうた（OnVo）  ]
アーティスト名 [ qfeuille3_v2 🥐⚓                      ]

⚠ チャンネル名の可能性があります
  題の中から:   [ なし ]

ニコニコ動画で古い投稿を探す  [ 探す ]
     ↓ 押すと（古い順）
  [ 両義_04 ]  sm12298171・2010-10-02
  [ Pangelino ] sm12305503・2010-10-03
```

⚠ の行はチャンネル臭があるときだけ出る。「ニコニコ動画で古い投稿を探す」は**どのマスにも出す**。

候補を押すとアーティスト名の欄が入れ替わる（データを書き換える。取り消しは 1 回ぶん持つ）。

一括では出さない。100 マスぶんの候補を並べても選べない。
並べ替えの下に「アーティスト名を確かめたいマス: 3 件」とだけ出し、押すとそのマスを順に選ぶ
（数えるのはチャンネル臭のあるマスだけ。転載は押してみないと分からないので数に入れない）。

## どこを直すか

| ファイル | 何を |
| --- | --- |
| `backend/sources/nicosearch.py`（新規） | スナップショット検索 API と一致度の並べ替え。`getthumbinfo` は `video.py` の定数を借りる |
| `backend/main.py` | `/artist-candidates?title=…&source=youtube` を足す |
| `backend/cache.py` | 結果を覚える（`SEARCH_TTL_BY_SOURCE` に `nicosearch` を足す。7 日） |
| `backend/searchcache.py` | R2 の控えにも入れる（`cache.sqlite3` はデプロイで消えるため） |
| `frontend/index.html` | 編集パネルの候補欄、チャンネル臭の判定（spec 1 の `trimName()` と同じファイル） |
| `docs/services-terms.md` | ニコニコのスナップショット検索 API の規約・上限・`_context` の決まりを書く |
| `docs/sources.md` | 候補の出どころとして書く |

## 守ること

- **1 秒に 1 リクエストまで**（スナップショット検索 API の目安）。押したときだけ引くので
  ふだんは問題にならないが、連打への備えとして間隔を空ける
- `_context` に `trackmento` を入れる（API の決まり）
- **検索語を恒常的に記録しない**。`searchcache.py` の既存の決まりと同じで、鍵は HMAC にして
  中身に題を入れない（プライバシーポリシーとの両立）

## やらないこと

- **YouTube 内での転載を見つけること**。ニコニコのスナップショット検索に当たる公開の API が
  YouTube にはない（Data API は鍵が要り、無料枠の単位も小さい）。概要欄も読まないので、
  YouTube から YouTube への転載は手がかりがない。**利用者が手で直すしかない**と割り切る
- YouTube の概要欄を読むこと（規約・壊れやすさ）
- 自動での差し替え（規則で確実に決まるものは spec 1 の A1・A2・G が受け持つ）
- ニコニコ以外への問い合わせ（otoDB・VocaDB は既に別の用途で引いている。
  東方アレンジ・ニコカラはどちらにも入っていないことが多く、当たりが少ない）
- 一括での候補提示（100 マスぶんは選べない）
